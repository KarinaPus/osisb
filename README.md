# Лабораторная работа 4 — вариант 9

Модель «Писатели–читатели» с приоритетом читателей. Читатели разделяют доступ к общему ресурсу; писатель получает его эксклюзивно. Первый читатель захватывает семафор ресурса, последний освобождает его. Поэтому новые читатели могут присоединяться к активной группе, даже когда писатель ожидает.

## Среда и сборка

- Windows 10/11
- C++20 и MinGW-w64 (например, MSYS2 UCRT64)
- Потоки создаются через `std::jthread`; синхронизация ресурса выполнена средствами Windows API: `CreateMutexW`, `CreateSemaphoreW`, `WaitForSingleObject`, `ReleaseMutex`, `ReleaseSemaphore`, `CloseHandle`.

Из корня проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build.ps1
```

## Запуск экспериментов

Стандартный режим выполняет по 60 операций на участника. Для индивидуального режима используется `OPERATIONS = BASE_OPERATIONS + STUDENT_ID * 5`, а начальное значение генератора — `SEED = 1000 + STUDENT_ID * 97`. Для ID `125`: 685 операций и seed 13125. Каждый последующий повтор использует seed, увеличенный на номер повтора минус один.

```powershell
.\build\lab4.exe --mode both --student-id 125 --trials 3 --output-dir data\latest
```

По умолчанию программа сравнивает от 3 до 8 читателей, 2 писателей и выполняет не менее 3 запусков каждой конфигурации. В указанной команде результаты сохраняются в `data\latest\standard.csv` и `data\latest\individual.csv`. Подробный потокобезопасный журнал состояний (с TID и RESOURCE=1) включается параметром `--verbose`; его лучше отключать при измерении производительности. Каждый CSV содержит параметры нагрузки, фазового сдвига, seed и тайм-аутов.

Основные параметры доступны через аргументы командной строки; полный список:

```powershell
.\build\lab4.exe --help
```

Параметры `--read-work-us`, `--reader-think-us`, `--write-work-us` и `--jitter-us` задают короткую вычислительную нагрузку и ее воспроизводимую вариацию. Она не используется для синхронизации: согласование выполняется Windows Mutex и Semaphore. `--reader-phase-ms` разносит моменты старта читателей. У ожиданий ограниченное время; срок испытания ограничивает начало новых операций, а уже начатая операция и очистка завершаются после него.

## Графики и схема

Построить два графика из необработанных CSV-данных (среднее время выполнения и среднее ожидание писателя):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\plot_results.ps1 -InputCsv .\data\latest\standard.csv -OutputPrefix .\graphs\latest-standard
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\plot_results.ps1 -InputCsv .\data\latest\individual.csv -OutputPrefix .\graphs\latest-individual
```

Скрипт сохраняет редактируемые SVG. Исходная диаграмма алгоритма находится в `diagrams\readers-writers.mmd`. Эксперимент можно проверить повторным запуском программы; тест корректности запускается так:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\smoke.ps1
```

Каждая строка CSV — один запуск. В ней есть seed, параметры, число успешных операций, среднее и максимальное ожидание писателей, тайм-ауты, нарушения инвариантов и пропускная способность. Графики строятся только по фактически записанным измерениям.

## Проверки корректности

Во время выполнения проверяется отсутствие одновременного чтения и записи, наличие не более одного активного писателя, корректный возврат счетчика активных читателей к нулю и завершение операций без неучтенных потерь. При тайм-ауте результат отмечается в CSV; ошибки Windows API и нарушения выводятся явно.
